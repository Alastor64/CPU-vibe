# 微架构设计

## 设计约束

实现目标是 RV32IM、Tomasulo 乱序执行、按序提交和参数化多发射。外部只暴露课程规定的
AXI4-Lite 接口，不增加调试端口。CSR、异常、FENCE、ECALL 和 EBREAK 不在课程要求内。

## 五个逻辑流水级

1. **IF**：产生取指地址，访问指令 Cache，按发射宽度向译码端提供连续指令。
2. **ID**：译码、分支预测、分配 ROB 和物理寄存器，完成寄存器重命名并写入发射队列。
3. **IS**：从保留站选择操作数已就绪的指令；从物理寄存器堆读取值并派发到执行单元。
4. **EX/MEM**：执行算术、乘除、分支和地址计算；访问数据 Cache 或 AXI4-Lite。结果
   通过公共数据总线唤醒等待指令。
5. **CM**：按程序顺序提交 ROB 队首，更新架构寄存器映射，写回 Cache 或发起退出 MMIO
   写事务。遇到分支误预测或状态恢复请求时，从该指令之后压缩前端。

级间可以插入流水寄存器，乘除法、Cache miss 和总线事务允许多周期停顿。这里的“五级”
是接口和控制责任划分，不用执行单元固定延迟来定义。

## 主要结构

### 前端

- 参数化发射宽度 `IssueWidth`，支持 1、2、4。
- 指令 Cache 与数据 Cache 分开，容量、块大小、组数和相联度参数化。
- 分支目标缓冲和方向预测器减少控制冒险；无论预测是否命中，都必须能够精确恢复
  投机状态。
- 指令跨 Cache 行或跨取指块时保持字对齐地址，不假设编译器生成未对齐指令。

### 重命名与提交

- 架构寄存器固定为 32 个，物理寄存器数量可配置。
- 投机映射表负责重命名；ROB 保存目的架构寄存器、旧物理寄存器和完成状态。
- 指令按发射组进入 ROB 和保留站，执行结果可乱序完成。
- 只有 ROB 队首能提交。提交时释放旧物理寄存器，并更新架构映射。
- 分支误预测时，以 ROB 中保存的重命名检查点恢复映射，并将误预测路径指令逐项压缩。

### 执行

- ALU 执行整数算术、逻辑、移位和比较。
- 乘除法单元实现 `MUL/MULH/MULHSU/MULHU/DIV/DIVU/REM/REMU`。除零和
  `INT_MIN / -1` 遵循 RISC-V 规定。
- 分支单元根据已就绪操作数解析条件并核对预测。
- Load/Store 单元完成地址生成、对齐检查和 Cache 访问。
- 多周期操作在完成时只广播一次结果，保留站据此唤醒依赖指令。

### 存储一致性

- 单核模型不实现缓存一致性协议。
- Store 在提交阶段写入数据 Cache 或发送 AXI 写请求，避免不可恢复的投机副作用。
- Load 在地址确定后访问数据 Cache；如果前方存在地址未确定的 Store，保守等待或
  经过地址消歧后继续。
- 退出写固定为向 `0x80000000` 发送 `WSTRB=4'hf` 的 32 位 AXI 写，并等待 `B`
  通道响应，随后停止退休新指令。

## 模块边界

计划按以下职责拆分 Chisel 模块，避免单个巨型 `StudentTop`：

- `Config`：所有可综合参数及合法性检查。
- `Frontend`：PC、预测器、I-Cache 和取指队列。
- `Decoder`：RV32IM 字段提取、立即数生成和控制信号。
- `Rename`：投机/架构映射表、空闲物理寄存器表和分支检查点。
- `Rob`：环形队列、完成状态和按序提交。
- `IssueQueue`：参数化保留站、操作数匹配和 age 选择。
- `Execution`：ALU、乘除单元、分支单元和 Load/Store 单元。
- `Cache`：参数化、可替换的 I/D Cache 存储体。
- `AxiMaster`：分离通道握手、请求队列、写响应和退出检测。
- `StudentTop`：课程 AXI4-Lite 端口与内部模块连接。

算术、译码、重命名、ROB、发射选择和存储子系统的组合路径需要分组或流水化，以满足
300 MHz 的最低频率目标。

## 参数集

至少提供以下参数，并在 CI 和回归脚本中验证：

| 参数 | 初始建议 |
| --- | --- |
| `IssueWidth` | 1、2、4 |
| `RobDepth` | 16、32、64 |
| `PhysicalRegisters` | 64、96、128 |
| `IssueQueueDepth` | 8、16、32 |
| `ICache` | 2–8 KiB，2–4 路 |
| `DCache` | 2–8 KiB，2–4 路 |

所有参数必须在 elaboration 时检查，例如容量为 2 的幂、物理寄存器数量不少于 32、
发射宽度属于支持集合。

## 实施次序

1. 建立自有 Chisel 构建、参数类和可综合的空顶层，验证 AXI 端口与 RTL 导出。
2. 完成 RV32IM 译码器和所有整数执行单元，用定向差分测试锁定语义。
3. 建立取指、单发射、按序执行和按序提交基线，先打通全部官方正确性程序。
4. 加入 I/D Cache、分支处理和 AXI 请求管理，降低外部内存延迟对性能的影响。
5. 加入 ROB、物理寄存器重命名和 Tomasulo 发射队列，实现乱序完成、按序提交。
6. 扩展到 2、4 发射，处理多写口、多分支、多访存和唤醒选择器的面积/时序压力。
7. 跑参数矩阵，记录 IPC、面积、频率和关键路径，完成报告数据。

## 验证层次

- Chisel 单元测试：译码、立即数、ALU、乘除边界、ROB/空闲表、发射选择。
- 定向程序测试：官方未覆盖的 RV32I 和 M 扩展指令、分支恢复、重名依赖、
  Load/Store 顺序、Cache miss 和 AXI 背压。
- 官方正确性测试：19 个 `correctness_*`，使用足够的周期上限。
- 官方性能测试：6 个 `perf_*`，记录周期、IPC 和几何平均值。
- 综合回归：Yosys + ASAP7 面积与 OpenSTA 时序；检查锁存器、未驱动信号和顶层端口。
